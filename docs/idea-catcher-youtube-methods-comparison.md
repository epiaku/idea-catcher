# YouTube summaries compared: transcript + LLM (`youtube`) vs Gemini chat (`youtube-gemini`)

**Compared:** 2026-10-01, on two videos
**Video 1:** [RAG + Langchain Python Project: Easy AI/Chat For Your Docs](https://www.youtube.com/watch?v=tcqEUSNCn8I) by pixegami (a technical tutorial, 16:41, uploaded 2023-11-20)
**Video 2:** [6 Proven Strategies That Turn Viewers In To Buyers](https://www.youtube.com/watch?v=RlX-tt9XrFo) by Ed Lawrence (a business talk, 17:05, uploaded 2026-09-16)
**Pages compared:** for each video, the `youtube` page and the `youtube-gemini` page in `output/clippings/` of `tmp/ic`, both made on the `youtube` profile (`gpt-6-sol`). Video 1 was made with prompts `youtube-2` and `youtube-gemini-2`. Video 2 was made with `youtube-3` and `youtube-gemini-4`, so it also shows whether the fixes after video 1 worked. The video 1 pages were checked first and are no longer in `tmp/ic` (the test repos were reset since), so their numbers here are from that check.
**Method:** every claim on every page was checked against the real transcript saved in the facts file (`…youtube.json`, 347 segments for video 1 and 530 for video 2) and against what Gemini originally wrote in the archived chat. Timestamps below are from the transcript.
**Why:** to decide which method to rely on, and whether the differences are real or only detail.

## The two methods

|                           | `youtube` (direct clip)                                                                                                  | `youtube-gemini` (Gemini chat clipping)                                          |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| **What the LLM gets**     | The real transcript, title, channel, description, chapters and counts, fetched by Python (yt-dlp and the transcript API) | Gemini's finished answer, copied from a web chat. The LLM only reformats it      |
| **Who watched the video** | Our code read the transcript                                                                                             | Gemini did, and we trust what it wrote                                           |
| **YouTube API call**      | Yes                                                                                                                      | None                                                                             |
| **Extra files**           | `.youtube.json` facts file next to the page                                                                              | None                                                                             |
| **Free checks (no LLM)**  | Yes: timestamps after the end of the video, tools not in the transcript                                                  | Not possible (no facts to check against)                                         |
| **Manual step**           | None (a clipped YouTube page is enough)                                                                                  | You run the prompt in Gemini first, then clip the chat                           |
| **Tokens (video 1)**      | 6,851 in / 1,012 out, about $0.024 at the prices in `.env.example`                                                       | Not logged. The input is a short chat, so expect a fraction of that              |

## Verdict in short

On both videos the two pages agree on the core: main purpose, the examples, the action plan, the main tips and the same core tools. A reader would learn the same thing from either. The differences are in **how much you can trust and verify the page**, and, as video 2 showed, in **a few defects on each side**.

**Rely on `youtube` as the main method; keep `youtube-gemini` as the fallback and as a second opinion.** It is the only one with real metrics, checkable timestamps and free checks. But it is not automatically the better page: on video 2 its Summary was useless and its free check raised a false alarm (both fixable, see the end), while the Gemini page carried more concrete numbers. A Gemini page's numbers can be wrong in ways nothing can catch (one was).

## What video 2 showed about the fixes made after video 1

**Confirmed working**
- **No tool drift from the advice sections.** The Gemini page's Tech Stack has nothing taken from Channel Application (the FastAPI problem of video 1 did not come back).
- **Published date and metrics on the direct page, metrics on the Gemini page.** Both are there.
- **The Epiaku business context.** Both Channel Application sections are tied to the digital product, the email list and an app waitlist, where video 1's were generic.
- **Chapters and links when there are none, or only promotion.** No empty sections, and no promotional link got through.

**New problems found**
1. The direct page's **Summary** describes the video description. For a video whose description is a sales pitch, that is the wrong thing to summarize.
2. The free check's **tool test is case and space sensitive** ("type form" is not found as "Typeform"), so a correct page got a warning box.
3. A Gemini page can repeat a **wrong number** from Gemini (30 to 40% "of" sales instead of "more" sales), and nothing checks it.
4. The reformat step writes **"Gemini says…"** inside the page text.
5. Gemini's Tech Stack can hold **generic categories** (email tools, page builders), which the reformat step copies.

## Is anything important missing in both?

Not much now. The three gaps found in video 1 (upload date, chapters, description links) are closed for the direct page, and for video 2 they were handled correctly. What is left:

- **A "which funnel for which price" overview.** The video's main idea is a choice by price and trust. The Gemini action plan has the thresholds in prose, the direct page spreads them over steps. A small table would serve both. This is a content suggestion, not a bug.
- **Upload age on the Gemini page.** Only the direct page shows the upload date, because Gemini's Metrics table has no such row. It matters for a tutorial (video 1 is from 2023), less for a talk.

## Pros and cons

### `youtube` (transcript + LLM)

**Pros**
- Real data: counts come from yt-dlp and Python writes them, so the LLM cannot invent them.
- Timestamps make every claim checkable (spot checks held on both videos), and the free checks flag wrong timestamps and tools not in the transcript.
- The facts file is kept, so the page can be rebuilt or audited.
- Works from a plain clip of the YouTube page. No extra manual step.
- Chapters and verified links come only from the real data.

**Cons**
- Needs YouTube to answer. Transcript fetching has been blocked from this machine before (429, see [the transcript research](idea-catcher-youtube-transcript-research.md)). A blocked fetch defers the note.
- No captions means no summary (the note is deferred, not guessed).
- More tokens: the whole transcript goes to the LLM (6,851 in for a 16-minute video).
- The Summary follows the video description, which can be promotion (video 2).
- A false alarm from the free check (video 2) and some noise in Tech Stack (video 1).

### `youtube-gemini` (Gemini chat + reformat)

**Pros**
- No YouTube API call, so it works when the transcript fetch is blocked.
- Cheap: the LLM only reformats a short answer.
- Often more concrete: class names and distances (video 1), prices and counts (video 2).

**Cons**
- A manual step each time, and the chat can be messy (video 1's needed two extra turns for the thumbnail).
- Nothing to verify against: an error looks the same as a fact. Video 2 had one (30 to 40% "of" sales).
- Metrics are Gemini's word. They were right on both videos (9,954 views matched the API on a later fetch), but there are no subscribers and no upload date, and nothing checks them.
- No timestamps.
- Gemini can leave sections out (it wrote no Summary in video 2) or pad the stack with generic categories.
- The reformat step can leak "Gemini says…" into the page.
